# AGENTS.md

## Project status

This repository implements the README frontend option as a McDonald's order controller prototype.

Use the current frontend stack:

- Vite+ (`vite-plus`) for dev/build/check/test commands
- React 19 with TypeScript
- Tailwind CSS 4
- shadcn/ui-style local components in `src/components/ui`
- Yarn 4 with `nodeLinker: node-modules` (`packageManager` is `yarn@4.17.0`)

Public deployment is handled by the user's Cloudflare automation. Do not start a manual Vercel or other third-party deployment unless the user explicitly asks.

## Commands

Before running package scripts, ensure Yarn 4.17.0 is active:

```bash
corepack prepare yarn@4.17.0 --activate
yarn install --immutable
```

Run locally:

```bash
yarn dev
```

Verify changes:

```bash
yarn check
yarn test
yarn build
```

`yarn test` runs both unit and browser-mode e2e projects. Use `yarn test:unit` or `yarn test:e2e` only when narrowing feedback during development.

`yarn test:e2e` uses Vitest Browser Mode with Playwright Chromium. If the browser binary is missing, install it with:

```bash
env -u PLAYWRIGHT_DOWNLOAD_HOST yarn exec playwright install chromium
```

The `env -u` matters in this environment because `PLAYWRIGHT_DOWNLOAD_HOST` may point to a mirror that does not have the required Playwright build.

## Implementation notes

- The order state machine lives in `src/order-controller.ts` and is covered by `src/order-controller.test.ts`.
- The React UI lives in `src/App.tsx` and is covered by `src/App.browser.test.tsx`.
- The UI demonstrates all order controller requirements in memory:
  - normal and VIP orders
  - unique increasing order numbers
  - VIP priority ahead of normal orders while preserving VIP FIFO order
  - bots process one order at a time for 10 seconds
  - idle bots immediately pick up newly pending orders
  - removing the newest bot returns its in-progress order to the pending queue with priority rules preserved
- Browser tests intentionally wait for the real 10-second processing interval instead of mocking timers.

## Editing guidance

- Use Vite+ test shims (`vite-plus/test`, `vite-plus/test/browser-playwright`) instead of importing from `vitest` or `@vitest/*` directly.
- Prefer changing `src/order-controller.ts` for scheduling/business-rule changes and then update unit tests first.
- Prefer changing `src/App.tsx` for presentation and interaction changes, then update the browser-mode test.
- Keep generated build output out of commits; production output is generated by `yarn build`.
