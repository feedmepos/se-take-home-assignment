## 1. 项目背景

麦当劳在疫情期间推进自动化烹饪机器人，以减少人力、提高效率。本项目的任务是实现一个 **订单控制器（Order Controller）**，管理订单从提交到完成的全流程，以及烹饪机器人（Bot）的调度。

**约束**：

- 所有数据 **内存存储**，无需持久化
- 使用 AI 辅助开发，但须 **自行测试** 并理解代码
- 控制范围在 **约 1 小时** 内可完成的原型，避免过度工程化

## 2. 目标与交付物

### 2.1 业务目标

构建可演示的订单管理系统原型，满足：

- 普通 / VIP 订单的排队与优先级规则
- 多 Bot 并行处理（每 Bot 同时仅处理 1 单）
- 每单固定 **10 秒** 处理时间
- Bot 动态增减及减 Bot 时订单回队

### 2.2 交付物（前端路径）

| 交付项 | 说明 |
|--------|------|
| GitHub 仓库 | Fork 原仓库并实现方案 |
| 公网可访问 URL | 部署在 Vercel / Netlify 等平台 |
| 文档 | 需求文档（本文档）+ 设计方案 |
| 可运行原型 | 面试第一轮展示 + 第三轮结对编程扩展 |

### 2.3 不在范围内

- 用户登录 / 会员系统 / 订单持久化
- 真实麦当劳品牌 UI / 复杂动画
- 后端 CLI（若选前端则不做）
- 微服务、消息队列等重型基础设施

## 3. 用户故事

| ID | 角色 | 故事 | 验收要点 |
|----|------|------|----------|
| US-1 | 普通顾客 | 提交订单后，订单进入 PENDING；Bot 处理完成后进入 COMPLETE | 状态流转可见 |
| US-2 | VIP 会员 | VIP 订单优先于所有普通订单；多个 VIP 之间按先来后到 | VIP 插队、VIP 间 FIFO |
| US-3 | 经理 | 可增加 / 减少 Bot；加 Bot 后立即处理 pending 订单；减 Bot 时正在处理的订单停止并回队 | +/− Bot 行为正确 |
| US-4 | 烹饪 Bot | 每次只处理 1 单，每单 10 秒 | 单 Bot 不并发多单 |

## 4. 功能需求

### 4.1 订单创建

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-01 | New Normal Order | P0 | 点击后新订单出现在 PENDING 区，类型为 Normal |
| FR-02 | New VIP Order | P0 | 点击后新订单出现在 PENDING 区，类型为 VIP |
| FR-03 | 订单编号 | P0 | 全局唯一、单调递增（官方示例从 #1001 起） |
| FR-04 | VIP 排队规则 | P0 | 新 VIP 排在所有 Normal 之前、所有已有 VIP 之后 |
| FR-05 | Normal 排队规则 | P0 | 新 Normal 排在队尾（所有 VIP 及已有 Normal 之后） |

### 4.2 Bot 管理

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-06 | + Bot | P0 | 每次点击创建 **1 个** Bot；若 PENDING 非空，新 Bot **立即** 取单处理 |
| FR-07 | − Bot | P0 | 每次点击销毁 **最新创建** 的 Bot |
| FR-08 | 减 Bot（空闲） | P0 | Bot 为 IDLE 时直接销毁，不影响任何订单 |
| FR-09 | 减 Bot（处理中） | P0 | 停止处理；订单回到 PENDING **原位置**（保持 VIP/Normal 优先级） |
| FR-10 | Bot 空闲 | P0 | PENDING 为空时，Bot 保持 IDLE，直到有新订单 |
| FR-11 | Bot 串行处理 | P0 | 每个 Bot 同一时刻只处理 1 个订单 |

### 4.3 订单处理

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-12 | 取单 | P0 | Bot 从 PENDING 按 VIP 优先于 Normal 的规则取队首订单 |
| FR-13 | 处理时长 | P0 | 取单后 **10 秒** 完成，订单进入 COMPLETE |
| FR-14 | 连续处理 | P0 | 完成后若 PENDING 仍有订单，同一 Bot 自动处理下一单 |
| FR-15 | 多 Bot 并行 | P0 | 多个 Bot 可同时各处理 1 单 |
| FR-16 | 完成时间 | P1 | COMPLETE 区展示完成时间，格式 `HH:MM:SS` |

### 4.4 业务规则摘要

| 规则 | 说明 |
|------|------|
| 角色优先级 | VIP 优先于 Normal；同角色内先来后到 |
| 取单顺序 | 始终从当前 PENDING 队列中最优先的订单开始 |
| 派单时机 | 新建 Bot、新建订单、订单完成后，有空闲 Bot 且有待处理订单时应自动派单 |
| 减 Bot 目标 | 始终移除 **最新创建** 的 Bot |
| 订单回队 | 处理中被减 Bot 的订单，回到被取走前的排队位置，而非队尾 |

## 5. 业务概念（领域语言）

本节描述系统涉及的 **业务概念**，不涉及具体代码实现。技术方案见 [design.md](./design.md)。

### 5.1 订单（Order）

一笔顾客提交的烹饪请求，具有：

- **编号**：唯一、递增
- **客户类型**：Normal 或 VIP（下单时确定，非用户账号）
- **状态**：待处理（PENDING）→ 处理中（PROCESSING）→ 已完成（COMPLETE）

### 5.2 烹饪机器人（Bot）

自动处理订单的设备，具有：

- **编号**：唯一、递增
- **状态**：空闲（IDLE）或处理中（PROCESSING）
- **约束**：同时最多处理 1 单；每单耗时 10 秒

### 5.3 队列区域

| 区域 | 含义 |
|------|------|
| PENDING | 等待 Bot 取走的订单 |
| PROCESSING | 正在被 Bot 处理的订单（可在 Bot 面板体现） |
| COMPLETE | 已完成的订单 |

## 6. UI 需求

### 6.1 操作区（P0）

| 控件 | 对应功能 |
|------|----------|
| New Normal Order | FR-01 |
| New VIP Order | FR-02 |
| + Bot | FR-06 |
| − Bot | FR-07 |

### 6.2 展示面板（P0）

#### PENDING 区

- 展示所有待处理订单
- 每条显示：**订单编号**、**客户类型（VIP / Normal）**
- 列表顺序反映实际排队顺序（VIP 在上，同类型先来后到）

#### Cooking Bots 区

- 展示所有 Bot
- 每条显示：**Bot 编号**、**状态（IDLE / PROCESSING）**
- PROCESSING 时显示：**正在处理的订单编号**、**剩余秒数倒计时**

#### COMPLETE 区

- 展示所有已完成订单
- 每条显示：**订单编号**、**完成时间（HH:MM:SS）**

### 6.3 交互要求

- 用户通过按钮操作后，界面应 **即时反映** 状态变化
- 所有官方功能需求（第 4 节）须可通过 UI 操作并观察到结果

## 8. 验收测试场景

### 8.1 基础流程

| # | 步骤 | 预期 |
|---|------|------|
| T-01 | 点 New Normal Order | PENDING 出现 #1001 Normal |
| T-02 | 再点 New Normal Order | PENDING 出现 #1002，排在 #1001 后 |
| T-03 | 点 + Bot | Bot #1 取 #1001，10s 后进入 COMPLETE |
| T-04 | 完成后 | Bot #1 IDLE；若 #1002 仍在 PENDING 则自动继续 |

### 8.2 VIP 优先级

| # | 步骤 | 预期 |
|---|------|------|
| T-05 | Normal #1001 → VIP #1002 → Normal #1003 | 队列顺序：#1002 VIP, #1001 Normal, #1003 Normal |
| T-06 | VIP #1004 插入上述队列 | #1002, #1004, #1001, #1003 |
| T-07 | 1 个 Bot 处理 | 顺序：#1002 → #1004 → #1001 → #1003 |

### 8.3 多 Bot 并行

| # | 步骤 | 预期 |
|---|------|------|
| T-08 | VIP #1001 + Normal #1002，+ Bot 两次 | Bot #1 处理 #1001，Bot #2 处理 #1002，并行 10s |

### 8.4 减 Bot

| # | 步骤 | 预期 |
|---|------|------|
| T-09 | 2 个 Bot IDLE，点 − Bot | 销毁 Bot #2 |
| T-10 | Bot #2 正处理 #1003，点 − Bot | Bot #2 销毁；#1003 回 PENDING 原位；计时停止 |
| T-11 | VIP 队列中 #1002 处理中被减 Bot | #1002 回到 VIP 段原位置，不掉到 Normal 段 |

### 8.5 编号与边界

| # | 步骤 | 预期 |
|---|------|------|
| T-12 | 连续创建 5 单 | 编号连续递增无重复 |
| T-13 | 无订单时点 + Bot | 创建 IDLE Bot，不报错 |
| T-14 | 无 Bot 时创建订单 | 订单停留 PENDING |
