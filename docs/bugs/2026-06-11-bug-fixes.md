## 1. .gitignore 模式匹配过宽

**文件**: `.gitignore`

**问题**: 模式 `order` 会匹配任何路径下名为 `order` 的文件或目录，导致 `internal/business/order/` 下的新文件被 git 忽略。

**修复**: 改为 `/order`，只在根目录匹配。

**关联**: 添加新文件 `constants.go`、`types.go` 时发现 `git add` 被 ignore。

## 2. dispatch() 缺少 nil 保护

**文件**: `internal/business/order/controller.go:112-115`

**问题**: `Queue.Pop()` 在队列为空时返回 nil。虽然 `dispatch()` 提前检查了 `Len() == 0`，但如果逻辑变更后 `Len()` 和 `Pop()` 不一致（如竞态条件），会导致 `o.Status = OrderProcessing` panic。

**修复**: 在 `Pop()` 后显式检查 nil 并 return。

## 3. RemoveAt 与 PushReturn 语义不一致

**文件**: `internal/business/order/queue.go` (已移除)

**问题**: `RemoveAt` 返回 `*Order` 时没有将 `heapItem.seq` 保存到 `Order.seq`。如果后续调用 `PushReturn`，order 的 `seq` 为 0（零值），将跳转到同优先级队列最前面，破坏 FIFO 语义。

**修复**: 方法已移除（生产代码未使用）。保留的 `Pop()` 和 `PushReturn()` 成对使用，`Pop` 在返回前保存 seq，`PushReturn` 使用该 seq 恢复位置。

**经验**: `container/heap` 的 `heap.Remove()` 返回元素时同样需要保存 seq。如果需要此功能，必须实现相同的 seq 保存逻辑。

## 5. Demo goroutine 泄漏风险

**文件**: `internal/business/order/demo.go:20-34`

**问题**: 使用裸 `chan struct{}` 控制 goroutine 生命周期。如果 `RunDemo` 在 `close(done)` 之前 panic，goroutine 永远收不到退出信号。

## 7. Unicode 右箭头导致 Windows 编码问题

**文件**: `internal/business/order/controller.go` (全局替换 `→` -> `->`)

**问题**: `→` (U+2192) 是非 ASCII 字符。Go 输出 UTF-8，但 Windows cmd/PowerShell 的 `>` 重定向和 `Get-Content` 在非 UTF-8 代码页下会乱码（显示为 `�?`）。

**修复**: 全部替换为 ASCII `->`。

**影响**: 所有 6 处 `record()` 调用中的 `→` 都改为 `->`：
- `PENDING`
- `picked by Bot #N (completes at HH:MM:SS)`
- `COMPLETED by Bot #N`
- `returned to PENDING`
- `IDLE (no pending orders)`

## 8. Demo 计时不足，Order #5 无法完成

**文件**: `internal/business/order/demo.go:52`

**问题**: 最后一个 `time.Sleep(demoDuration + 500ms)` = 2500ms 不够。Order #5 在 ~2800ms 时入队，但上一个完整周期（N1/N2 完成）在 ~4200ms，N5 完成在 ~6200ms。2500ms 的等待只能等到 ~5300ms，N5 仅处理了 1100ms/2000ms。

**修复**: 改为 `time.Sleep(4 * time.Second)`，确保 N5 有足够时间完成并进入 IDLE。

## 经验总结

### container/heap 使用要点
- `Less(i, j)` 在 i 优先级高于 j 时返回 true
- heap 通过索引重排维持堆序，同一优先级内的 FIFO 不能依赖索引比较（`i < j`），必须使用外部 seq 计数器
- `Pop()` 返回堆末元素（非 root），这是 `container/heap` 接口的约定
- seq 保存：`Pop()` 后必须将 `heapItem.seq` 写回 `Order.seq`，供 `PushReturn` 使用

### Windows 兼容性
- Go 输出 UTF-8，但 Windows 默认代码页非 UTF-8（通常是 GBK/CP936）
- 非 ASCII 字符在 PowerShell `>` 重定向和 `Get-Content` 中可能乱码
- 为跨平台兼容，避免在输出中使用非 ASCII 字符
- `cmd /c "command > file"` 比 PowerShell 的 `>` 更可靠

### 测试命名陷阱
- `TestXxx_Yyy` 格式下，vscode/vim 等工具的 Test Explorer 可能无法正确识别
- 在 `.opencode/skills/` 或 AGENTS.md 中记录测试命名约定
