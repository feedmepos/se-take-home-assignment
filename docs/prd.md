# FeedMe 软件工程师线上笔试作业 完整中文翻译
## 作业说明
以下是本次岗位面试前的线上笔试作业，你需要完成：
1. 理清业务场景与使用需求，如有疑问可联系面试官进一步确认；
2. 选用前端或后端技术栈完成需求开发；
3. 可借助AI辅助开发，但必须自行完成全部测试；
4. 为你认为需要说明的模块编写配套文档；
5. 面试时携带源代码与可正常运行的演示原型。

## 业务场景
麦当劳在后疫情时代推进业务升级，计划搭建自动烹饪机器人，以此减少人工人力、提升门店运营效率。你是该项目的软件工程师，本次任务是开发一套订单调度控制器，用于管控全流程订单流转。

## 用户故事
### 普通顾客视角
作为麦当劳普通顾客，我提交订单后，希望订单进入**待处理（PENDING）**区域；烹饪机器人完成制作后，订单自动流转至**已完成（COMPLETE）**区域。

### VIP会员视角
作为麦当劳VIP会员，我下单后，我的订单需要比所有普通顾客订单优先处理；但若队列中已有其他VIP订单，我的订单需排在已有VIP订单后方。

### 门店经理视角
作为麦当劳门店经理，我需要能增减门店可用烹饪机器人数量：
- 新增机器人时，机器人需立刻开始处理待处理队列里的订单；
- 减少机器人时，该机器人正在制作的订单会暂停处理。

### 烹饪机器人视角
单台机器人同一时间仅能接收并处理1份订单，每份订单固定耗时10秒制作完成。

## 硬性需求
1. 点击「新建普通订单」，生成新订单并展示在**待处理区**；
2. 点击「新建VIP订单」，生成新订单放入待处理区：
   - 排在所有普通订单前方；
   - 排在所有已存在VIP订单后方；
3. 订单编号全局唯一、自增递增；
4. 点击「+新增机器人」：
   - 创建一台机器人，立刻拉取待处理队列订单开始制作；
   - 订单抓取满10秒后，移入**已完成区**；
   - 制作完成后，若待处理区仍有订单，机器人继续取下一单；
5. 若待处理区无任何订单，机器人进入**空闲（IDLE）**状态，等待新订单进入；
6. 点击「-移除机器人」：
   - 销毁最新创建的那台机器人；
   - 若该机器人正在制作订单，立即中断制作，订单退回待处理队列原有排序位置（保留VIP/普通订单优先级规则）；
7. 无需持久化存储数据，所有逻辑仅在内存中运行即可。

## 可运行原型二选一实现（前端/后端）
### 方案1：前端实现
- 技术栈、编程语言、框架不限；
- UI应用需编译打包，并部署至任意可公开访问的网页平台；
- 必须提供可视化界面，完整演示上述全部需求；
- 支持用户交互操作，完整还原麦当劳订单管理系统流程。

### 方案2：后端实现
- 技术限定：Go（Golang）或 Node.js；
- 程序为命令行交互工具（CLI），可在GitHub Actions中直接运行；
- 在项目scripts目录下必须实现3个脚本文件：
  - test.sh：执行单元测试的脚本；
  - build.sh：CLI程序编译打包脚本；
  - run.sh：启动运行CLI程序的脚本；
- CLI运行输出全部写入 `result.txt` 文件；
- `result.txt` 所有日志必须携带 **时:分:秒（HH:MM:SS）** 时间戳，用于记录订单完成时间；
- 代码遵循GitHub Flow工作流：通过提交Pull Request合并代码；
- 保证GitHub Actions全部校验流程执行通过。

补充说明：下一轮面试必须演示交互式命令行程序，候选人需提前准备，现场演示交互式指令处理逻辑。

## 提交要求
1. Fork 本仓库，任选前端/后端方案完成开发；
   - 前端方案：部署至公网可访问地址；
   - 后端方案：使用Go/Node.js开发，兼容GitHub Actions环境；
2. 严格遵循GitHub Flow流程，提交Pull Request；
3. test.sh 内所有单元测试必须全部通过；
4. result.txt 需输出完整、有业务意义的运行日志；
5. 全部输出日志附带HH:MM:SS时间戳，用于追溯订单完成时刻；
6. 提交Pull Request，确保后端校验工作流 `backend-verify-result` 检测通过；
7. 为所有需要说明的模块编写配套文档。

## 完成作业小贴士
1. 反复测试，确保原型完整可用、全部需求达标；
2. 可借助AI开发工具辅助，建议总开发时长控制在1小时内，禁止过度设计；
3. 务必读懂并理解每一行代码逻辑，遵循规范工程开发标准；
4. 代码尽量简洁干净，整洁规范的代码是重要加分项，不要堆砌繁杂冗余技术。
