# Project Structure

This repository now contains a TypeScript implementation of the FeedMe order controller, plus a small static frontend demo that reuses the same controller logic.

## Top-Level Files

```text
.
|-- .github/workflows/backend-verify-result.yaml
|-- .gitattributes
|-- .gitignore
|-- docs/project-structure.md
|-- frontend/
|-- package-lock.json
|-- package.json
|-- scripts/
|-- src/
|-- test/
|-- vercel.json
`-- tsconfig.json
```

## Source Folders

### `src/`

Backend and shared domain logic.

```text
src/
|-- cli.ts
`-- orderController.ts
```

- `orderController.ts` contains the in-memory order queue, bot lifecycle, simulated clock, snapshots, and event logging.
- `cli.ts` contains the non-interactive simulation used by `scripts/run.sh` and a dependency-free terminal dashboard for interview demonstration.

The controller is intentionally framework-free so it can be reused by tests, CLI, and frontend without duplicating business logic.

### `test/`

Node test runner specs.

```text
test/
`-- orderController.test.ts
```

The tests compile through TypeScript first, then run against `dist/test/**/*.test.js`.

### `frontend/`

Static frontend demo.

```text
frontend/
|-- app.ts
|-- index.html
`-- styles.css
```

- `app.ts` imports the shared controller from `src/orderController.ts`.
- `index.html` loads the compiled frontend script from `dist/frontend/app.js`.
- `styles.css` is plain CSS and does not require a build step.

Run `npm run build` before serving the frontend so `dist/frontend/app.js` exists.

### `scripts/`

GitHub Actions entrypoints and local build helpers.

```text
scripts/
|-- build-static-site.mjs
|-- build.sh
|-- result.txt
|-- run.sh
`-- test.sh
```

- `build-static-site.mjs` packages the static frontend into `dist/public` for Vercel.
- `test.sh` installs dependencies with `npm ci`, compiles TypeScript, and runs unit tests.
- `build.sh` installs dependencies with `npm ci` and runs the TypeScript build.
- `run.sh` compiles TypeScript and runs `dist/src/cli.js`, writing output to `scripts/result.txt`.
- `result.txt` is the sample simulation output checked by the workflow.

## Generated Folders

These are intentionally ignored by Git:

```text
dist/
node_modules/
```

- `dist/` is generated by `tsc`.
- `dist/public/` is generated by `npm run build:site` for Vercel deployment.
- `node_modules/` is generated by `npm ci` or `npm install`.

## Build Flow

```text
TypeScript source
  |-- src/*.ts
  |-- test/*.ts
  `-- frontend/app.ts
        |
        v
tsc --project tsconfig.json
        |
        v
dist/
  |-- src/*.js
  |-- test/*.js
  `-- frontend/app.js
```

The backend CLI runs from `dist/src/cli.js`. The frontend imports from compiled files under `dist/`.

## Current Architecture

The application has one source of truth:

```text
OrderController
|-- used by CLI
|-- used by unit tests
`-- used by frontend demo
```

This keeps the behavior consistent across both backend and frontend:

- VIP priority applies to pending orders only.
- FIFO is preserved within VIP and normal queues.
- Bots process one order at a time.
- Processing takes 10 simulated seconds.
- Destroying the newest processing bot returns its order to pending.
- No persistence is used.

## Commands

```bash
npm ci
npm run build
npm test
node dist/src/cli.js
npm run cli
```

Or use the assignment scripts:

```bash
./scripts/test.sh
./scripts/build.sh
./scripts/run.sh
```

For Vercel deployment:

```bash
npm run build:site
npx vercel --prod
```

The interactive dashboard is available with:

```bash
npm run cli
```

Dashboard commands:

```text
n       create normal order
v       create VIP order
+       add bot
-       remove newest bot
t 10    advance simulated time by 10 seconds
s       refresh status
h       show help reminder
q       quit
```
