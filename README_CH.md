## FeedMe 软件工程师技术测试任务
以下是面试前的技术测试任务。你需要：
1. 理解场景和用例。你可以联系面试官进行进一步澄清。
2. 使用**前端或后端组件**实现需求。
3. 尽可能使用 **AI** 完成需求，但需进行自行测试。
4. 为你认为需要的任何部分提供文档。
5. 将源代码和运行原型带到面试环节。

### 场景
麦当劳在 COVID-19 期间正在进行业务转型。他们希望构建自动化烹饪机器人，以减少劳动力并提高效率。作为该项目的一名软件工程师，你的任务是创建一个处理订单控制流的订单控制器。

### 用户故事
以下是部分用户故事：
1. 作为麦当劳的普通顾客，在我提交订单后，我希望看到我的订单进入“PENDING（待处理）”区域。在烹饪机器人处理完我的订单后，我希望看到它进入“COMPLETE（完成）”区域。
2. 作为麦当劳的 VIP 会员，在我提交订单后，我希望我的订单在所有普通顾客的订单之前被处理。但是，如果已有 VIP 会员的订单，我的订单应该排在他的订单之后。
3. 作为麦当劳经理，我想增加或减少餐厅中可用的烹饪机器人数量。当我增加机器人时，它应该立即处理任何待处理的订单。当我减少机器人时，正在处理的订单应保持未处理状态。
4. 作为麦当劳机器人，它一次只能提取并处理 1 个订单，每个订单需要 10 秒才能完成处理。

### 需求
1. 点击“New Normal Order（新建普通订单）”时，新订单应显示在“PENDING”区域。
2. 点击“New VIP Order（新建 VIP 订单）”时，新订单应显示在“PENDING”区域。它应排在所有现有“普通”订单之前，但在所有现有“VIP”订单之后。
3. 订单号应该是唯一且递增的。
4. 点击“+ Bot（增加机器人）”时，应创建一个机器人并开始处理“PENDING”区域内的订单。在提取订单 10 秒后，订单应移至“COMPLETE”区域。然后，如果“PENDING”区域还有剩余订单，机器人应开始处理另一个订单。
5. 如果“PENDING”区域没有更多订单，机器人应保持 IDLE（空闲）状态，直到有新订单进来。
6. 点击“- Bot（减少机器人）”时，应销毁最新的机器人。如果该机器人正在处理订单，它也应该停止处理。订单应返回其在“PENDING”区域的原始位置（保持 VIP/普通订单优先级）。
7. 此原型不需要数据持久化，你可以在内存中执行所有过程。

### 功能原型
你必须实现如下所述的**前端或后端**组件：

#### 1. 前端
- 你可以自由使用**任何你选择的框架和编程语言**
- UI 应用程序必须在任何公开可访问的 Web 平台上进行编译、部署和托管
- 必须提供一个展示上述所有需求的界面
- 应允许用户与麦当劳订单管理系统进行交互

#### 2. 后端
- 你必须使用 **Go (Golang) 或 Node.js** 进行后端实现
- 后端必须是一个可以在 GitHub Actions 中执行的 CLI 应用程序
- 必须在 `script` 目录下实现以下脚本：
  - `test.sh`：包含单元测试执行步骤
  - `build.sh`：包含 CLI 应用程序的编译步骤
  - `run.sh`：包含运行 CLI 应用程序的执行步骤
- CLI 应用程序的结果必须打印到 `result.txt`
- `result.txt` 输出必须包含 `HH:MM:SS` 格式的时间戳，以跟踪订单完成时间
- 必须遵循 **GitHub Flow**：创建一个 Pull Request 将你的更改提交到此仓库
- 确保所有 GitHub Action 检查都成功通过
- **注意**：下一轮面试必须提供交互式 CLI 实现。候选人应准备好演示交互式命令处理。

#### 提交要求
- Fork 此仓库并使用前端或后端实现你的解决方案
- **前端选项**：使用任何技术栈部署到公开可访问的 URL
- **后端选项**：必须在 Go 或 Node.js 中实现，并在 GitHub Actions 环境中运行
  - 遵循 GitHub Flow 流程并提交 Pull Request
  - `test.sh` 中的所有测试必须通过
  - `result.txt` 文件必须包含 CLI 应用程序的有意义的输出
  - 所有输出必须包含 `HH:MM:SS` 格式的时间戳，以跟踪订单完成时间
  - 提交 Pull Request 并确保 `backend-verify-result` 工作流通过
- 为你认为需要的任何部分提供文档

### 完成此任务的建议
- 测试，测试，再测试。确保原型功能正常并满足所有需求。
- 利用编码智能体在 1 小时内完成任务范围，不要过度设计。但是，请确保你阅读并理解你的代码在做什么，并应用良好的工程实践。
- 尽可能保持实现简洁，代码整洁是一个加分项，不要引入各种花哨的技术。
