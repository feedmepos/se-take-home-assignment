## Why

麦当劳需要一个订单追踪与厨房机器人管理系统的前端原型，用于演示订单从提交到完成的完整生命周期、VIP 优先级调度和机器人资源管理。所有订单全局可见，无需用户登录。引入经理角色控制机器人增减权限，并通过活动日志追踪所有订单和机器人的生命周期事件，使原型更具可观测性。

## What Changes

- 新增角色系统：顾客（默认）可创建订单，经理可创建订单 + 管理机器人
- 新增活动日志：记录所有订单创建、处理开始、处理完成、退回、机器人增减等事件
- 新增订单提交功能：支持普通订单和 VIP 订单两种类型
- 新增 PENDING 区域：展示所有待处理订单，VIP 自动排在普通订单前面
- 新增 COMPLETE 区域：展示所有已完成订单
- 新增机器人管理：经理角色可动态增加/减少烹饪机器人
- 新增机器人自动处理逻辑：每个机器人每次处理一个订单，耗时 10 秒
- 新增机器人销毁回退逻辑：被销毁机器人的进行中订单回到 PENDING 队列原位置
- 技术栈使用 React + Vite

## Capabilities

### New Capabilities

- `manager-role`: 角色管理 — 支持顾客（默认）和经理两种角色切换，只有经理可操作机器人增减
- `order-submission`: 订单提交功能 — 支持普通订单和 VIP 订单创建，订单号唯一递增，订单进入 PENDING 队列并遵守优先级排序
- `order-queue-management`: 订单队列管理 — PENDING 区域按 VIP 优先排序展示所有订单，COMPLETE 区域展示所有已完成订单
- `bot-management`: 机器人管理 — 经理专属操作，增加/减少机器人，自动取单处理，销毁时进行中订单回退
- `activity-log`: 活动日志 — 记录订单创建、处理开始、处理完成、退回、机器人增减等事件的时间线

## Impact

- 纯前端 React SPA，使用 Vite 构建，无需后端 API
- 无数据持久化需求，所有数据（含日志）存于内存
- 需 Node.js 环境用于开发和构建
- 订单和机器人全局共享，所有用户（同一浏览器）可见
